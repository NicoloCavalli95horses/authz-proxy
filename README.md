# Graph-Based GUI Exploration for BAC Detection

This project is a research prototype for the automated detection of **Broken Access Control (BAC)** vulnerabilities in modern web applications through **graph-based GUI exploration**, **HTTP response mutation**, and **behavioral graph comparison**. Specifically, it is design to test **feature gating** soundness.

The framework combines three complementary components:

1. **GUI Explorer** — automatically explores the application's user interface by interacting with clickable elements and reconstructing navigation states.
2. **Mutation Proxy Server** — intercepts and rewrites HTTP responses according to configurable mutation rules, simulating privilege escalation, premium feature unlocking, role changes, and other access-control violations.
3. **Graph Comparison Engine** — builds application state graphs from both the original and mutated executions, then compares their structure and observed behaviors to identify inconsistencies that may reveal BAC

Unlike traditional scanners that focus primarily on HTTP requests, this approach analyzes the **observable application behavior** after HTTP response tampering. The system explores the application twice:

1. **Baseline execution**, where the application behaves normally.
2. **Mutated execution**, where selected server responses are programmatically modified by the proxy.

Each execution generates a directed graph representing discovered GUI states, user interactions, DOM changes, and network activity. The resulting graphs are then compared to detect newly reachable states, hidden functionalities, additional API calls, or altered navigation paths that may indicate unauthorized access.


## Motivation

Modern SPA web applications increasingly rely on client-side logic to implement feature gating, making traditional endpoint-based security analysis insufficient for identifying access control flaws.

This project investigates whether **interaction with a tampered front-end can lead to the discovering of authorization issue**, addressing the following questions:
- What happens when a front-end receiving tampered HTTP responses believes it's dealing with a user with higher privileges, even though it isn't?
- Are new requests generated by this client appropriately rejected by the web server? Can new GUI states be immediately available simply by tricking the client logic? 

The framework is intended as an experimental platform for research on automated security testing, web application exploration, and graph-based behavioral analysis.

## Setup

- Create a .env file following the .env.example

- Install and run PostgreSQL with
> ./install.sh

- Run proxy server, launch Chrome and Playwright with
> ./start.sh
